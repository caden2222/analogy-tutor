# Analogy Tutor — hosted QKV milestone

A plain HTML/CSS/JavaScript learning interface with Express, an interactive Three.js library, and two explicitly selected reply modes:

- **Scripted demo:** fixed QKV examples. No model API calls and no API key required.
- **Generated · Groq API:** QKV explanations generated by the hosted `openai/gpt-oss-120b` model. No model weights are downloaded. Conversation context is sent to Groq, and generated answers may be inaccurate.

The design, graphics, scripted content, separate in-memory sessions, reset and safe text rendering are preserved. No accounts, database, deployment or additional topics were added.

## Run the scripted demo

Use Node.js 22.9 or newer (the existing Node 22.15 installation supports the environment-file flag):

```powershell
Set-Location C:\Users\caden\Downloads\analogy-tutor
npm install
npm start
```

Open **http://localhost:3000**, leave Reply mode on **Scripted demo**, and choose a starting option. Do not open the HTML directly or use Live Server: requests need the Express backend. Ctrl+C stops Node; `npm run dev` enables automatic restart while editing.

`npm install` prepares locally served Three.js modules through the postinstall script. If lifecycle scripts are disabled, run `node scripts/copy-three.cjs` manually. No CDN, external 3D model assets or bundler is needed.

## Configure Groq locally

1. Create or use your [Groq console account](https://console.groq.com/). Check that its plan is **Free** and review the [actual organization limits](https://console.groq.com/settings/limits). Do not enable a paid upgrade as part of this setup. The app cannot verify your account's billing plan.
2. Create an API key in the console. Keep it private: do not send it in chat, screenshots, Git commits or command-line examples.
3. Create the local environment file without overwriting an existing one:

```powershell
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
notepad .env
```

4. In that local editor, replace `replace_with_your_key` with your real key. Keep the model setting as `GROQ_MODEL=openai/gpt-oss-120b`. Save and close the editor. Do not paste the key into PowerShell commands or this chat.
5. Restart with `npm start`. Node reads `.env` through `--env-file-if-exists`. Existing shell environment variables take precedence over `.env`.
6. Open the app and explicitly choose **Generated · Groq API** before starting. This makes real provider requests when you interact; our automated tests do not.

`.env` and related secret files are ignored by Git; `.env.example` contains placeholders and is tracked. Express serves **only `public/`**. It does not expose the environment file, server/provider source, instructions, tests or project metadata. Keys are used in backend Authorization headers and are never sent to the frontend or logged.

## Costs and provider data handling

Groq currently lists a recurring, rate-limited Free plan, separate from temporary promotional credits. For the chosen model, the published Free plan limits are 30 requests/minute, 1,000/day, 8,000 tokens/minute and 200,000/day; exact organization limits may differ. A free plan has no published scheduled trial expiry, but availability, limits and terms can change. This is not a promise of free service forever.

The published paid price is US$0.15 per million input tokens and US$0.60 per million output tokens. If your key belongs to an account with paid billing enabled, requests can incur charges. The code never upgrades billing, switches models/providers or falls back to a paid service. We made **no live model requests** during implementation.

These local defaults bound attempts:

| Setting | Default | Purpose |
| --- | --- | --- |
| `GROQ_MODEL` | `openai/gpt-oss-120b` | Model name; must support the configured strict JSON schema and reasoning setting |
| `MODEL_TIMEOUT_MS` | 25000 | Abort a stalled upstream call; browser waits five seconds longer |
| `MODEL_MAX_OUTPUT_TOKENS` | 1024 | Maximum completion tokens, including the model's applicable reasoning/output budget |
| `MODEL_CONTEXT_CHARS` | 8000 | Maximum retained history text sent, separate from system instructions and the current message |
| `GENERATED_REQUESTS_PER_MINUTE` | 2 | Global rolling-minute attempt limit for this Node process |
| `GENERATED_REQUESTS_PER_DAY` | 50 | Global daily attempt limit; UTC date boundary |

At most one generated request runs at a time across this local app. All attempts, including failures, count toward its request caps. The caps reset when Node restarts. They are **application safeguards, not provider billing controls** and do not represent a currency budget. Token-based provider quotas may still be reached before these caps. After two generated turns, wait a minute before another; scripted mode remains available.

Groq says inference content is not retained by default, with reliability/abuse retention up to 30 days and legal exceptions. Zero Data Retention can be enabled in the console's Data Controls; usage metadata is still collected. Review the provider's policy before submitting personal or confidential content. Reset clears the app's memory, not anything already processed or retained by Groq.

Official references: [model and pricing](https://console.groq.com/docs/model/openai/gpt-oss-120b), [rate limits](https://console.groq.com/docs/rate-limits), [billing](https://console.groq.com/docs/billing-faqs), [data handling](https://console.groq.com/docs/your-data), [API](https://console.groq.com/docs/api-reference#chat-create), [structured outputs](https://console.groq.com/docs/structured-outputs).

## What changed, in simple terms

```text
public/app.js              Browser fetch, mode selection and text-only rendering
public/index.html          Existing page plus the Reply mode selector
public/styles.css          Existing design plus styles for that selector
server.js                  Async chat route, isolated sessions, throttles and retry coordination
server/provider.js         Existing scripted provider, now async
server/content.js          Unchanged scripted teaching text
server/groq-provider.js    Server-only HTTPS request and response validation
server/tutor-instructions.md  Readable QKV teaching and accuracy rules
.env.example               Configuration placeholders; no real credentials
```

The browser sends its message/action and a unique request ID to Express. Its session ID identifies that page's history and chosen mode. Express selects the provider and waits using `await`; generated mode sends the instructions and bounded context to Groq using native Node `fetch`. It validates the completed JSON sections before saving the turn and returning it. The browser validates mode and response shape, then creates HTML elements using **textContent**, so returned HTML is displayed as text.

The instructions ask for one short familiar story, a concept mapping, one limitation and an optional check. Follow-ups answer the specific misunderstanding, preserve the story where useful and prioritize the real QKV mechanism. Format validation cannot verify teaching accuracy; real model outputs still need evaluation.

Generated responses use typed sections instead of assuming every story has exactly four paragraphs. Responses are clearly labelled generated and potentially inaccurate. Scripted responses keep their existing labels and examples. A session stays in one mode until **Start again**, which clears its server history and unlocks mode selection.

## Sessions, context and retries

- Each page load gets its own random session ID, kept only in browser memory. Histories are not shared across tabs/users.
- Sessions expire after 30 minutes idle; server restart clears them all. Refresh abandons the old session until expiry.
- The rolling history holds 100 messages. Generated sessions also retain the original first turn separately to preserve the story. The provider sends that turn and up to 10 recent messages, within the configured character budget; oversized messages are shortened and marked. Missing context should cause clarification rather than invented recall.
- Each session remembers the last 20 successful request IDs/results. A retry after a lost response returns the cached result without another generation or history append.
- Identical **simultaneous** requests share the same in-flight promise. Different requests or reset while a turn is running receive 409 rather than racing the history.
- Failed calls append no learner/model turn. The learner's input stays in the textbox; retry reuses the operation. There are no automatic upstream retries.
- An explicit retry after a failed/aborted upstream call can make a new provider request and consume quota or incur charges on a paid account. A network timeout cannot establish whether Groq processed the earlier request; this is not an exactly-once billing guarantee.
- Reset clears the selected session's app history and retry cache before the page clears. Other sessions are unaffected.

## Input/output and error handling

Client messages must be non-empty and at most 2,000 characters. Express accepts JSON bodies up to 8 KB and rejects unknown modes, actions or fields. Configuration numbers and model names are validated without printing their values.

The generated provider uses strict structured output, then separately validates section types, length and required story sections. It rejects malformed JSON, truncated generations, empty sections, oversized sections, replies over 6,000 text characters and HTTP bodies over 64 KB. It never displays reasoning traces, upstream error bodies or partial answers.

Visible errors distinguish missing setup, rejected credentials/access, unavailable models, provider quota, local throttling, network failures, timeout and invalid output. Errors never silently become scripted answers. Switching to scripted mode requires **Start again** and an explicit selection.

## Manual success checks

1. Without configuring a key, scripted mode must still show the library story, misconception correction and weighted example. The 3D scene and weight slider must still work.
2. With no key, choose generated mode and start: expect a useful setup error, retained input and no scripted substitution. No model request is sent in this case.
3. After entering the key locally and confirming your account's plan, choose generated mode. This step makes real calls. Try a starting story, then “Is the value the score?”. Expect a labelled generated reply that corrects that specific distinction using the story. Wait a minute after two calls because of the local limit.
4. Test the technical explanation: scores come from scaled query/key dot products, softmax produces weights, and weighted values are summed. The supplied [0.8, 0.2] example must produce [8, 2] and explicitly say the weights were supplied.
5. Try `<img src=x onerror=alert(1)>`: it must appear as text with no image or alert. DevTools Offline mode should show an error and keep input; restore the connection before retrying.
6. Use Start again to clear the conversation and change mode. Open another tab to confirm its context is independent.
7. `/server.js`, `/server/groq-provider.js`, `/server/tutor-instructions.md` and `/.env` must return 404.

The local server binds to 127.0.0.1 only. To choose another port, set `$env:PORT = '3001'` before `npm start`, then open http://localhost:3001.
